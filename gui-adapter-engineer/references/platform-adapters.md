# Platform adapter recipes

Official documentation below was read on **2026-10-13**. Recheck the relevant operating-system and app versions when implementing. These recipes guide building adapters. The included runtime in this suite is for macOS; Windows, Linux, browser, and app-service adapters are not implemented by this reference.

## Shared behavior

Expose a small common set: identify target; discover capabilities; observe controls and image; activate window; invoke supported control action; replace editable text; type at focus; click; send shortcut; scroll; drag; and observe the result. Treat each operation as optional. Report missing capability rather than simulate success.

Bind a connection to the exact app process and window, or browser session and page. Record its version and startup identity. Recheck identity after reconnects and restarts. Limit observations to the authorized target. Store coordinates with their space, origin, dimensions, scale, and capture time. Compare an image's pixels with the operating system's logical coordinates before input.

An app's supported control action can be independent of focus. Global keyboard and pointer input usually depend on actual focus and visibility. Check the adapter's real rules. Before pointer input, check the target position and covering windows. A background screenshot does not prove a window is receiving input.

Report uncertain delivery as unknown. Inspect current state before repeating an action that could create another message, payment, file, or job. Release only this adapter's held input. Do not clear the person's unrelated pressed keys or overwrite the clipboard without a task reason and a restoration plan.

## macOS: included runtime

Use `AXUIElementCreateApplication(pid)` to obtain the chosen process's accessibility object. Read supported attribute names and values with `AXUIElementCopyAttributeNames` and `AXUIElementCopyAttributeValue`. Discover actions with `AXUIElementCopyActionNames`. Check `AXUIElementIsAttributeSettable` before `AXUIElementSetAttributeValue`; invoke a supported action through `AXUIElementPerformAction`. Unsupported actions, invalid objects, missing app support, and incomplete messaging have distinct errors. Apple notes that an action timeout can occur during modal processing and does not necessarily mean failure. Inspect the app before repeating it. [Apple Accessibility functions](https://developer.apple.com/documentation/applicationservices/1462091-axuielementperformaction?changes=_8)

Check `AXIsProcessTrustedWithOptions` without requesting a prompt when the task is discovery. Check capture and event-posting access independently. Apple's privacy system, often called TCC, controls which programs can use protected desktop features. A harness sandbox is another restriction; a sandbox denial does not prove macOS privacy permission is absent. [Accessibility trust](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions), [Core Graphics access functions](https://developer.apple.com/documentation/coregraphics/core-graphics-functions?changes=latest_maj_3_1_1&language=objc)

Capture the selected app or window using ScreenCaptureKit's `SCShareableContent`, `SCContentFilter`, and screenshot or stream APIs available on the deployment version. Use actual capture metadata to calculate dimensions and scale. Apple recommends `SCContentSharingPicker` when obtaining user selection. That picker grants selected-content access for a sharing session; broad recording access is a separate route. Neither route grants accessibility control. The included helper uses existing rights and does not open permission dialogs. [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit?changes=latest_be_8), [Apple's picker explanation](https://developer.apple.com/videos/play/wwdc2023/10053/)

The supplied helper uses Apple's installed `/usr/sbin/screencapture` command for exact-window images, after the ScreenCaptureKit reader stalled during testing on this Mac. It names the already observed native window, excludes shadows and attached windows, checks the app generation and window bounds before and after the read, and reports measured image dimensions and scale. It uses fixed command arguments without a shell, interaction, clipboard output, or full-display fallback. Inspect the installed command's usage or manual before adapting this route; its permission and capture behavior must be verified on the target host. ScreenCaptureKit remains a platform implementation option rather than the supplied helper's active image path.

Use `CGEvent` keyboard and mouse events only after checking the actual foreground app, focused window, target ownership, and geometry. Treat secure fields separately from ordinary text. The included runtime refuses secure-field text operations and omits their values. A window image can still reveal private content; minimize captures and retention.

## Windows: build recipe

Build a UI Automation client. UI Automation is Microsoft's control tree and behavior interface. Identify the process and window handle, read properties and child elements, and request supported control patterns. Patterns are capabilities such as Invoke, Value, Selection, Scroll, and Window. Do not assume all patterns exist because the control looks like a button or editor. A Text pattern alone does not establish a writable Value pattern. [UI Automation control patterns](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-controlpatternsoverview), [Pattern interfaces](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/control-patterns-and-interfaces)

Read the current privilege limits before designing access to elevated apps or protected desktops. Microsoft describes separate ordinary, elevated, and system-level boundaries. UIAccess is not a universal grant across them. Never auto-elevate the agent or alter its manifest to evade a denied operation. [UI Automation access limits](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)

Use Windows Graphics Capture for a selected window or display. Check `GraphicsCaptureSession.IsSupported()`. The system picker returns a `GraphicsCaptureItem`; use its size when constructing the frame pool. Verify image format and high dynamic range handling. Native interoperation with a window handle requires its own supported implementation. [Windows screen capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)

Use `SendInput` as an input fallback. Check returned event count and keyboard state, and pair this adapter's presses with releases. It is limited to apps at an equal or lower integrity level, which is Windows' process privilege ranking. Its return value and error do not identify privilege blocking as the cause. Focus, display scaling, multiple monitors, and a secure desktop remain separate checks. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

## Linux: build recipe

Use AT-SPI to read the chosen app's accessible object tree and its supported interfaces. AT-SPI is the Linux desktop accessibility service. Query name, role, state, process, children, and interface support. Enumerate Action operations before invoking an action. Use EditableText only when exposed, and distinguish insertion from entire-content replacement. Character offsets are not necessarily byte offsets. [Accessible objects](https://docs.gtk.org/atspi2/class.Accessible.html), [Action](https://docs.gtk.org/atspi2/iface.Action.html), [EditableText](https://docs.gtk.org/atspi2/iface.EditableText.html)

On Wayland, build capture and input through an available desktop portal rather than assuming unrestricted desktop input. Wayland is a Linux display system; a portal is the desktop's approved service for granting operations. Check the installed backend, interface version, available devices, and available source types. Create a RemoteDesktop session, select devices and sources, and start it through the user-approved portal flow. Use only granted devices. [RemoteDesktop portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html)

The RemoteDesktop documentation recommends `ConnectToEIS()` after session start. EIS supplies an input connection used by the libei library. Once established, send input exclusively over that route; the portal's `Notify*` methods must not be mixed with it. Absolute pointer positions use a stream's logical coordinate space. ScreenCast supplies PipeWire streams and metadata. PipeWire is the desktop media transport. When the installed version supports it, follow the documented `pipewire-serial` targeting rather than assume a reusable stream node number stays valid. [RemoteDesktop input](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html), [ScreenCast](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html)

Do not substitute X11-only input assumptions for a Wayland adapter. For an X11 target, inspect and document the actual server, input route, permissions, and capture mechanism separately. An AT-SPI connection alone does not supply screenshots or unrestricted input.

## Browser: build recipe

Use a supported browser driver and a proven automation session. WebDriver is the standard command protocol for browser control. Its session routes include finding elements, interacting, navigating, and taking screenshots. Bind actions to the exact session, top-level page, frame, and element. The specification says implementations usually launch another browser instance; using the person's existing browser depends on the implementation. A new test session is not proof of attachment to an existing signed-in tab. [WebDriver](https://www.w3.org/TR/webdriver/)

WebDriver BiDi adds two-way messages and subscriptions. Its official source, inspected here as an editor's draft, defines `session.subscribe`, `browsingContext.captureScreenshot`, and `input.performActions` with an explicit page context. Pin the supported method set and verify the chosen browser's implementation. Handle stale elements, blocked dialogs, interrupted navigation, and unsupported methods. Native browser chrome and operating-system dialogs may require the platform adapter. Do not export cookies or session tokens to force an attachment. [Official BiDi source](https://raw.githubusercontent.com/w3c/webdriver-bidi/main/index.bs)

## Electron and application services: build recipe

Electron uses web pages inside desktop windows. Start with the operating-system adapter unless an app has an established control interface. Its `--remote-debugging-port` enables renderer debugging over HTTP; `--inspect` controls the separate main-process inspector. Enabling either is a change, not discovery of an already active route. Inspect startup flags and process ownership first. [Electron switches](https://www.electronjs.org/docs/latest/api/command-line-switches), [Main-process debugging](https://www.electronjs.org/docs/latest/tutorial/debugging-main-process/)

Electron's testing guide describes experimental Playwright support and custom app drivers. These can launch another app instance or require app code. Neither proves control of the user's current desktop session. Adding instrumentation, restarting, weakening isolation, or opening a debugger beyond the task needs explicit scope. Preserve Electron's sandbox and context isolation. [Automated testing](https://www.electronjs.org/docs/latest/tutorial/automated-testing), [Security](https://www.electronjs.org/docs/latest/tutorial/security)

For any app service, record endpoint ownership and purpose, version, transport, request shape, supplied authentication, session attachment, and allowed operations. A service found in code is source-only until exercised. Use credentials supplied through an authorized mechanism; do not search keychains, app storage, process memory, cookies, or logs for tokens. Verify a harmless read first, then a scoped reversible change with an observed result. If the route operates a backend without changing the GUI, report that distinction.
